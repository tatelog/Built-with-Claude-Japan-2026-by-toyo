# CLAUDE.md（下書き：キックオフ時に新しいリポジトリの直下へ置く）

## このプロジェクト

手書きのまま、建築確認申請まで。iPad と Apple Pencil で RC 造の板状マンションを描くと、図面・3D・構造計算・法令チェック・申請図書まで出る道具。
大会「Built with Claude Code: Japan 2026」（2026/11/2 12:00 〜 11/10 14:00 JST）の作品。
出発点は `docs/IDEA_EGG.md`（代表のアイデア）。決まったことはプロジェクトハブにある。

## 依頼主への話し方

- 依頼主は建設会社の代表。エンジニアではない
- 日本語で、結論から、短く。専門用語は避け、使うなら一言で説明する
- 「正本」という言葉は使わない
- 代表が決めることは、選択肢と自分のおすすめを添えて聞く。決まっていることは聞き直さない

## 進め方

1. 段階を飛ばさない：GrillMe → 概要と主張 → 要件 → スコープ → 作業フロー → 基本設計 → 応用設計 → DB → 画面 → 工程 → 実装
2. 各段の成果はハブの該当ページに書き、状態を「案」→「確定」にする。代表が確定と言うまで次の段の設計に入らない
3. 実装は部品ごとに子セッションで並行して進める。部品同士は共通データだけでつなぐ
4. 毎晩、全部品をつないだ通しテストを回し、結果と待ち時間（即答・追認・熟考）をハブに記録する

## プロジェクト管理（ハブ）

- ハブの URL とデータの形は `docs/KICKOFF.md` にある
- タスクの状態：着手したら「進行中」、終わったら「確認待ち」、代表が確認したら「完了」
- 代表の判断が要るものは担当「代表」でタスクにする（「未決事項」に自動で並ぶ）
- ハブ本体を書き換えるのは司令塔セッションだけ。子セッションは自分の担当の Artifact とタスクの状態だけを更新する

## セッションの回し方

- 司令塔セッションが子セッションを立てる。最初の指示に、担当範囲・読むファイル・守ること・成果の置き場所・報告のしかたを書く
- 立てたらハブの「セッション」に登録し、タスクをひも付ける
- 子セッションは区切りごとに司令塔へ send_message で報告する（試したこと／試せなかったことを分けて）
- 子セッションは自分のブランチで作業し、司令塔がまとめる。他のセッションのブランチは書き換えない
- Artifact へのコメントが届いたら、そのページを管理するセッションに渡し、スレッドに「何を誰に頼んだか」を返信する。スレッドは代表が閉じる

## 開発のやり方

- 使うモデルとエフォートは `.claude/settings.json` で固定する（キックオフ時に代表の決定どおりに設定）。変えるときは代表に確認する
- 計算と判定（法令・構造・数量）はプログラムで行い、同じ入力から毎回同じ結果が出るようにする。AI に計算させない
- 法令・告示の数値は、条文番号を添えてコードに書く
- 小さくコミットし、何を変えたかを日本語で書く
- iPad の Safari／Chrome（WebKit）で動くことを毎回確かめる

## 守ること

- 作品は大会期間中にゼロから作る。大会前のコード・自作の既存コードは持ち込まない
- デモで見せるものはすべて OSS ライセンスで公開する（Japan 大会の規約で確定させる）
- 他社の AI API は製品に使わない。AI は Claude のみ
- 実案件のデータ・自社単価・施主情報は、リポジトリにも Artifact にも入れない
- 動画・ページの素材は権利がはっきりしたものだけ。自社の図面は施主名・所在地をぼかす
- 有料の規準書・積算資料の中身は取り込まない
