## 1. ひとことで

**敷地を入れると、法規の範囲で建てられる最大ボリュームが出て、
そこに板状マンションの基本設計が自動で組み上がり、3D（BIM）と概算見積まで一気に出る。
設計を変えれば金額の増減が即わかり、AIに計画とコストの相談ができる道具。**

- 使う人：ゼネコンの担当者（着工前の作り込み・事業提案の段階）
- 困りごと：土地の話が来るたびに
  ボリュームチェック → 住戸の割付 → 数量拾い → 概算 を別々の人・別々の道具で回しており、
  「この土地で何戸・いくらで建つか」を出すまでに日数がかかる
- 大会テーマとの対応
  - 「ひとりの深い知見から」：マンションの計画・積算・作り込みの実務知識
  - 「人手不足の解決」：設計・積算の担当が足りない中で、初期検討を数分で回す

## 2. 一連の流れ（この順番で画面が進む）

```
① 敷地      敷地形状・前面道路・用途地域・指定建ぺい率/容積率 などを入力
   │         （AIが敷地資料のPDF・画像から読み取って自動入力）
② ボリューム  建ぺい率・容積率・各種斜線から「建てられる最大の形」を3Dで表示
   │
③ 基本設計   板状マンションを自動配置
   │         住戸幅・奥行・階数・片廊下・階段/EVコア・住戸タイプ構成
④ BIM・住戸表 3D表示、戸数・専有面積・延床面積・レンタブル比
   │
⑤ 概算見積   部材数量を自動で拾い、単価を掛けて工種別に集計
   │
⑥ 案の比較   案A/案Bの戸数・面積・工事費の差と、その理由
   │
⑦ AI相談    「戸数を最大に」「工事費をあと5,000万円下げたい」
              → AIが案を出し、承認すると③〜⑤が組み直される
```

審査で一番見せたいのは **住所と敷地を入れてから数分で
「何戸・延床何㎡・工事費いくら」まで3Dで出る場面** と、
**AIの提案で建物と金額が同時に変わる場面**。

## 3. 各段階の中身と割り切り

### ① 敷地
- 入力：敷地形状（多角形）、前面道路の位置と幅員、方位、用途地域、
  指定建ぺい率・容積率、高度地区・日影規制の有無
- AIの役割：概要書・測量図・重要事項説明書などのPDFや画像から上記を読み取って入力欄を埋める
  （人が最終確認する）
- 余力があれば：住所から地図・周辺建物の3D（国交省 PLATEAU のオープンデータ）を表示

### ② ボリューム
- 対象にする規制：建ぺい率、容積率（前面道路幅員による低減を含む）、
  道路斜線、隣地斜線、北側斜線、絶対高さ・高度地区
- 対象外：天空率、日影規制の時刻別計算（余力があれば簡易版）
- 表示：結果は **検討用の目安** と明記する（確認申請の代わりにはならない）

### ③ 基本設計（板状マンション）
- ボリュームの中に「住戸モジュール」を並べて自動配置
- 決められる条件：構造（RC造）、住戸タイプ（例：2LDK 70㎡ / 3LDK 75㎡）と構成比、
  住戸幅・奥行、片廊下、階高、コア（階段・EV）の位置、1階の用途（住戸/エントランス/駐車場）
- 人が手で直せる：階数・住戸数・住戸タイプの入れ替え、コア位置の移動
- 対象外：中廊下型・塔状・雁行など複雑な形、住戸内の間取り詳細

### ④ BIM・住戸表
- 柱・梁・壁・スラブ・開口・バルコニー・廊下を部材として持つ3Dモデル
- 住戸表：戸数、住戸タイプ別の内訳、専有面積合計、延床面積、容積対象面積、レンタブル比

### ⑤ 概算見積
- 数量：コンクリート量・型枠面積・鉄筋量（係数で概算）・外壁面積・内装面積・建具数・
  バルコニー・EV台数 など
- 単価表は **自社単価または仮の単価**。市販の積算資料（建設物価など）の数値は取り込まない
- 出力：工種別内訳、総額、延床坪単価、1戸あたり工事費

### ⑥ 案の比較
- 案を保存して並べ、戸数・面積・工事費の差と「どこで差が出たか」を表示

### ⑦ AI相談（Claude）
- 例：「戸数を最大にしたい」「3LDKを増やしたい」「工事費をあと5,000万円下げたい」
- AIは条件を変えた案を複数試算し、根拠付きで提示 → 利用者が承認すると反映
- **金額・面積・法規の計算はプログラムが行い、AIには計算させない**（数字がぶれない）。
  AIは「何を変えるか」を考えて理由を説明する役

## 4. Claude の使い方

- **作品を作る**：Claude Code（Max 5x プラン）
- **作品の中で動くAI**：Claude API（$500 クレジット）、モデルは Claude Opus 5.5
  - 敷地資料の読み取り：PDF・画像を渡し、決まった形（JSON）で条件を返させる
  - 計画・コスト相談：通常の API ＋ ツール連携。AIに渡す道具の例
    - `敷地と規制を読む` / `現在の計画を読む` / `見積を読む`
    - `条件を変えて試算する`（反映せず、戸数・面積・金額の差だけ返す）
    - `計画に反映する`（利用者が承認したときだけ）
  - Managed Agents は今回は使わない（1画面で完結し、短期間では仕組みを増やさない方が安全）

## 5. 技術の構成（参考）

- ブラウザで動く Web アプリ（インストール不要、審査員が URL ですぐ触れる）
- 画面：React + TypeScript、3D は three.js
- 法規・配置・数量・金額の計算：画面側のプログラム（すべて同じ入力から同じ結果が出る）
- AIとの通信：小さなサーバー（Node.js）経由で Claude API を呼ぶ（API キーをブラウザに置かない）

## 7. デモの筋書き（3分想定）

1. 敷地の概要書PDFを入れる → AIが条件を読み取り、敷地と最大ボリュームが3Dで立ち上がる
2. 「板状マンション」を選ぶ → 住戸が自動で並び、「42戸・延床3,100㎡・工事費◯億円」が出る
3. AIに「戸数は保ったまま、工事費をあと5,000万円下げたい」と相談
   → AIが3案を根拠付きで提示 → 1案を承認 → 建物と金額が同時に変わる
4. 締め：「土地の話が来てから数日かかっていた初期検討が、打合せ中にその場で終わる」
