## 1. ひとことで

**iPad と Apple Pencil で Jw_cad のようにRC造板状マンションを描くと、その場で図面と3Dになり、
構造計算・法令チェック・建築確認申請図書一式（BIM図面審査用IFC含む）まで出る。**

建物の種類を「RC造の板状マンション」1種類に絞ることで、
広く浅くではなく **その1種類については申請図書一式まで出る** ところまで作り切る。

## 1.5 この作品が示す主張

1. **専用の Decision API がなくても、数値の判断はできる。**
   ペンをデジタイザとして使い、描いた線の長さ・角度・位置をその場で数値にする。
   画像解析ではなく数値を Claude に渡し、「この線は何か」を型の決まった答えで判断させる。
   → 「この判断には Jev のような Decision API が必須」という見方に対する反証
2. **それでも、判断専用の高速な仕組みは必要。**
   数値で渡せば判断は正確になるが、一筆ごとに描く速さで答えるには今の汎用モデルでは遅い。
   Jev のような「型の決まった判断を高速に返す」機能が Claude にもあれば、
   手書きがそのまま設計になる。待ち時間の実測でこれを示す。

## 2. 全体の構成（8つの部品 ＋ 共通の建物データ）

すべての部品は **共通の建物データ（M0）** だけを読み書きする。
部品同士が直接つながらないので、大会初日から並行して作れる。

```
      iPad ＋ Apple Pencil
              │ 手書きの線
        M1 手書き認識 ─────────┐
              ▼                │ AIの指摘を手書きで直す
   ┌──── M0 建物データ ◀──────┤
   │      （通り芯・柱・梁・壁・スラブ・開口・住戸・敷地）
   ├─▶ M2 作図・3D
   ├─▶ M3 法令チェック
   ├─▶ M4 構造計算 ──▶ 断面・配筋を M0 に書き戻す
   ├─▶ M5 申請図書・IFC
   ├─▶ M7 概算コスト
   └─▶ M6 AI審査官（M2〜M5 の結果を読んで指摘）──┘
```

| 部品 | 中身 | AI（Claude）の役割 |
|---|---|---|
| **M0 建物データ** | 建物を表す共通の形式。全部品の約束事 | — |
| **M1 作図入力（Jw_cad 流 × Apple Pencil）** | iPad ＋ Apple Pencil。Jw_cad と同じく、すべての線を始点・終点の座標を持つ直線・円弧として扱う。端点・交点・中点への吸着（Jw_cad の読取点）、ペンを押してはらう方向でコマンドを呼ぶ（クロックメニューの考え方）、長さ・角度の数値入力。Jw_cad 形式（JWW）と DXF で書き出し | 線のまとまりが何か（柱・梁・壁・開口・住戸）を判断し、建物データに変換 |
| **M2 作図・3D** | 配置図・各階平面図・立面図・断面図・求積図・伏図・軸組図・部材リスト、3D | — |
| **M3 法令チェック** | 集団規定（建ぺい率・容積率・道路/隣地/北側斜線・日影・天空率）、単体規定（採光・換気・界壁・防火区画・直通階段と歩行距離・2方向避難・廊下幅・非常用照明・排煙）、省エネ、バリアフリー | 条文から判定ルールを起こす。指摘の文章化と条文の引用 |
| **M4 構造計算** | 荷重の拾い（固定・積載・地震・風・雪）→ 応力解析 → 許容応力度の検定 → 層間変形角・剛性率・偏心率 → 保有水平耐力（Ds・Fes）→ 断面算定・配筋 → 基礎 | 結果の読み解き、断面の見直し案 |
| **M5 申請図書・IFC** | 確認申請書（第二号様式）、建築計画概要書、施行規則第1条の3の添付図書と明示事項、構造計算書、省エネ計算書、BIM図面審査の入出力基準に沿った IFC ＋ PDF | 図書間の整合チェック |
| **M6 AI審査官** | 図書一式を、指摘事例集と条文に照らして審査し、指摘を出す。直し方の案も出す | 中心的な役割 |
| **M7 概算コスト** | 同じ建物データから数量を拾い概算 | — |

### 反応の速さ（他社APIは使わず、Claude とプログラムだけで作る）

| 層 | 担当 | 速さ | 中身 |
|---|---|---|---|
| **即答** | プログラム（幾何計算） | 線を描き終えた瞬間 | 直線・円弧への当てはめ、吸着、「たぶん壁」の仮判定を即表示 |
| **追認** | Claude（軽いモデル・決まった形で返す） | 数百ms〜数秒 | 線のまとまりを数値で渡し、柱/梁/壁/開口/住戸を確定。仮判定と違えば静かに直す |
| **熟考** | Claude（上位モデル） | 数秒〜 | 法令チェック、構造計算の読み解き、申請図書の審査、直し方の提案 |

- 描く手は止めない。画面は即答で進み、Claude の答えが後から追いつく
- 各層の待ち時間を実測し、提出物に載せる

## 限界と、より改善しうる領域（作品の締めとして示す）

「今ここまで素晴らしいものができた。ただ、ここはまだ改善しうる」を、実測の数字で示す。

| 領域 | 今の限界（実測で示す） | 改善しうる方向 |
|---|---|---|
| AIの判断の速さ | 一筆ごとの判断に◯秒。描く速さに追いつくには0.2秒以内が必要 | 型の決まった判断を高速に返す仕組み |
| iPad のブラウザ | Bluetooth 直結不可、ペンの点の間引き | 現場の道具として使えるペン入力 |
| 告示 | PDF 中心で機械が読める形でない | 告示の機械可読化 |
| 建築確認 | BIM図面審査に外部からつなぐ窓口がない | 申請・審査の外部連携 |
| 構造計算 | 正式な申請は認定プログラムが前提 | 公開された計算エンジンを認める仕組み |
| 計算規準 | 規準書が有料の書籍 | 規準の公開 |

計算と判定（M3・M4・M7）は **プログラムで行い、同じ入力から毎回同じ結果が出る** ようにする。
AIは「読む・ルールを起こす・審査する・直し方を考える」を担う。
これにより、数字はぶれず、AIの強みは最大限に使う。

## 3. 「本物」であることの証明

- **実案件との照合**：御社の過去のRC造マンション1件分の構造計算書・確認申請図書と、
  同じ建物を手書きで入れて出した結果を比較し、主要な数値の一致を示す
  （実案件のデータは照合にだけ使い、公開・提出物には匿名化した数値のみ載せる）
- **指摘事例の再現**：国交省・大阪府・愛知県の指摘事例を、わざと誤りを入れた建物で再現し、
  M6 が見つけられることを示す
- **BIM図面審査への対応**：2026年4月から始まった BIM図面審査の入出力基準に沿った IFC を出す

## 4. デモの筋書き

1. タブレットに通り芯と柱・壁を手書き → その場で平面図と3Dが立ち上がる
2. 住戸を割り付ける → 構造計算が走り、柱・梁の断面と配筋が決まる
3. AI審査官が「北側斜線に抵触」「2方向避難が取れていない住戸がある」などを条文付きで指摘
4. 指摘箇所を手書きで直す → 再計算 → 指摘が消える
5. 「申請図書を出力」→ 確認申請書・図面一式・構造計算書・IFC がそろう
6. 実案件の構造計算書と数値を並べて、一致していることを見せる

## 7. 申請図書の扱い

出力は「建築士が確認して記名・押印すれば申請に出せる状態の図書一式」を目指す。
申請の責任は建築士にあるため、最終的な確認は人が行う（既存の一貫構造計算ソフトや
CAD と同じ位置づけ）。
