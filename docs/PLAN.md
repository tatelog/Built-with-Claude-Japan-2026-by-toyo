## 1. ひとことで

**ブラウザで作図すると、その場で3Dの建物と概算見積が出来上がり、
設計を変えれば金額の増減が即座にわかり、AIにコストの相談ができる道具。**

- 使う人：ゼネコンの担当者（着工前の作り込み段階）
- 困りごと：設計がまだ固まらない段階で「この変更でいくら変わるか」を出すのに、
  毎回 数量拾い → 単価入れ → 集計 を手でやり直しており、時間と人手がかかる
- 大会テーマとの対応
  - 「ひとりの深い知見から」：建設現場の積算・作り込みの実務知識
  - 「人手不足の解決」：積算担当者が足りない中で、検討の回転を速くする

## 2. 画面と機能

| # | 機能 | 内容 |
|---|---|---|
| A | 作図（2D平面） | 通り芯・柱・壁・開口（窓/扉）・床スラブを描く。階高と階数を設定 |
| B | 3D表示（BIM） | 描いた平面から自動で立体化。部材ごとに材料・仕様の情報を持つ |
| C | 数量の自動拾い | コンクリート量・型枠面積・鉄筋量（係数で概算）・仕上面積・建具数 |
| D | 概算見積 | 単価表を掛け、工種別（躯体/仕上/建具…）に集計。表と合計を常時表示 |
| E | 設計変更の金額差 | 「案A/案B」を保存し、比べると増減額と理由（どの部材がいくら）を表示 |
| F | AI相談（Claude） | 「あと500万円下げるには？」→ 代替案と根拠、金額差を提示。承認すると図面に反映 |
| G | AIに作図を頼む（余力があれば） | 「RC造3階建て事務所、延床600㎡」→ たたき台の建物を自動生成 |
| H | IFC書き出し（余力があれば） | 本物のBIMソフトに持っていける形式で保存 |

審査で一番見せたいのは **A→B→D がつながる瞬間** と **F で AI が案を出し、
図面と金額が同時に変わる瞬間**。

## 3. 範囲の割り切り（9日間で完成させるため）

- 構造は **RC造** に絞る（躯体数量の拾い方が明確なため）
- 壁は直交（縦横）のみ。曲線・斜め壁は対象外
- 建物は1棟。外構・設備は対象外（または一式計上）
- 鉄筋は配筋図からではなく **コンクリート1㎥あたりの係数** で概算
- 単価は **自社単価または仮の単価表** を使う。
  市販の積算資料（建設物価など）の数値は著作権の関係で取り込まない

## 4. Claude の使い方

- **作品を作る**：Claude Code（Max 5x プラン）
- **作品の中で動く AI**：Claude API（$500 クレジット）
  - モデル：Claude Opus 5.5
  - 方式：通常の API ＋ ツール連携。AI に渡す道具の例
    - `モデルを読む`（部材一覧・仕様）
    - `見積を読む`（工種別金額）
    - `変更を試算する`（実際には反映せず金額差だけ計算）
    - `変更を反映する`（利用者が承認したときだけ）
  - 金額の計算そのものは AI ではなくプログラムが行う（数字がぶれない）。
    AI は「何を変えるか」を考え、理由を説明する役
  - Managed Agents は今回は使わない（やり取りが1画面で完結し、
    仕組みを増やすほど9日間で壊れやすくなるため）

## 5. 技術の構成（参考）

- ブラウザで動く Web アプリ（インストール不要、審査員がすぐ触れる）
- 画面：React + TypeScript、3D は three.js
- AI との通信：小さなサーバー（Node.js）経由で Claude API を呼ぶ
  （API キーをブラウザに置かないため）
- 公開：審査員が URL で触れる形にする

## 7. デモの筋書き（3分想定）

1. 空の画面から RC 造3階建て事務所を数分で描く → 3D が立ち上がり見積が出る
2. 「外壁をタイルから吹付に変えたら？」→ 増減額が部材ごとに出る
3. AI に「あと500万円下げたい。性能は落としたくない」と相談
   → AI が3案を根拠付きで提示 → 1案を承認 → 図面と金額が同時に変わる
4. 締め：「積算担当が半日かけていた検討が、打合せ中にその場で回る」
