## 1. ひとことで

iPad と Apple Pencil で、RC 造の板状マンションを手で描く。
描いたその場で図面と 3D になり、構造計算・法令チェック・建築確認申請図書一式（BIM 図面審査用の IFC を含む）まで出る。

建設の現場を知っている人間として、「描く → 計算する → 審査に出す」までが別々の人・別々の道具に分かれていて、
1 件の検討に何日もかかっていることをずっと変えたかった。

## 2. 私が言いたいこと（主張）

1. **専用の Decision API がなくても、数値の判断はできる。**
   ペンをデジタイザとして使い、描いた線の長さ・角度・位置をその場で数値にする。
   画像を解析するのではなく、数値を Claude に渡して「この線は柱か、壁か、開口か」を判断させる。
   「この判断には Jev（TypeSafe AI）のような Decision API が必須」という見方への反証にしたい。
2. **それでも、判断専用の高速な仕組みは必要。**
   一筆ごとに描く速さで答えるには、今の汎用モデルでは遅い。待ち時間を実測して、
   「この機能が Claude にもあれば、手書きがそのまま設計になる」と示したい。

## 3. 背景：設計は一周して、手に還る

- DWG という拡張子は「Drawing（図面）」から来ている。1980 年代、AutoCAD（1982 年）はデジタイザ
  （タブレットと 16 ボタンカーソル）で紙の図面をなぞって数値にする使い方が主流だった
- 手の感覚は「手書き → デジタイザ → マウス → タブレット」と移るたびに遠ざかった。
  タブレットで手は戻ってきたが、残るのは「絵」で、数値にはならなかった
- 私の作品で、手書きのまま建物のモデルまで作れるところへ戻る。ただし元の場所ではなく、一段上に
- 要検証：「紙のデジタル化が最優先の目的だった」「デジタイザとの親和性が普及の決定打」という言い方の強さ。
  DWG は仕様が公式に公開されておらず、Open Design Alliance が解析した経緯がある

## 4. やりたいこと（要望の種。まだ要件ではない）

- Apple Pencil の動きを、座標・筆圧・傾き・時刻の数値で受け取る
- 線は直線と円弧だけで描く前提。端点・交点・中点・通り芯に吸着させる（Jw_cad の読取点、クロックメニューの感覚）
- 線のまとまりを柱・梁・壁・スラブ・開口・住戸として判断し、建物のデータにする
- 図面一式（配置図・平面図・立面図・断面図・求積図・伏図・軸組図・部材リスト）と 3D を自動で描く
- 法令チェック：建ぺい率・容積率・各種斜線・日影・天空率、採光・換気・界壁・防火区画・避難、省エネ・バリアフリー
- 構造計算：荷重 → 応力 → 許容応力度 → 層間変形角・剛性率・偏心率 → 保有水平耐力 → 断面・配筋 → 基礎
- 申請図書：確認申請書（第二号様式）、建築計画概要書、施行規則第 1 条の 3 の添付図書と明示事項、構造計算書、
  省エネ計算書、IFC・PDF、Jw_cad（JWW）・DXF
- 「AI 審査官」：図書一式を条文と指摘事例集で審査し、指摘と直し方を出す。指摘の箇所を手で直すと再計算・再審査
- 概算コスト（同じ建物データから）
- 反応の速さは 3 段で作りたい：即答（プログラム、描き終えた瞬間）／追認（Claude 軽量モデル）／熟考（Claude の上位モデル）
- 計算と判定はプログラムで行い、同じ入力から毎回同じ結果が出るようにしたい。AI には計算させない

## 5. 範囲の考え

- 建物の種類は **RC 造の板状マンション（片廊下）1 種類**に絞り、その 1 種類は申請図書一式まで出す。機能は削らない
- 正式な申請の代行はしない。「建築士が確認して記名すれば出せる状態」までを目指す
- S 造・木造・SRC 造、塔状・中廊下・雁行は対象外

## 6. 最後に示したい「限界と、より改善しうる領域」

| 領域 | 今の限界（実測で示す） | 改善しうる方向 |
|---|---|---|
| AI の判断の速さ | 一筆ごとの判断に ◯ 秒。描く速さに追いつくには 0.2 秒以内が必要 | 型の決まった判断を高速に返す仕組み |
| iPad のブラウザ | Bluetooth 直結不可、ペンの点の間引き | 現場の道具として使えるペン入力 |
| 告示 | PDF 中心で機械が読める形でない | 告示の機械可読化 |
| 建築確認 | BIM 図面審査に外部からつなぐ窓口がない | 申請・審査の外部連携 |
| 構造計算 | 正式な申請は認定プログラムが前提 | 公開された計算エンジンを認める仕組み |
| 計算規準 | 規準書が有料の書籍 | 規準の公開 |

## 7. 守ること（私の判断と、前回大会の規約から）

- 他社の AI API は製品に使わない。AI は Claude のみ（Jev は要望の根拠として名前を出すだけ）
- 前回大会（Built with Opus 4.6）の規約：デモで見せるものはすべて OSS ライセンスで公開、作品は期間中にゼロから。
  自作の既存コードも持ち込まない（Japan 大会の規約は要確認）
- OpenSees は使わない（組み込みに商用ライセンスが必要）。有料の規準書・積算資料の中身は取り込まない
- 実案件のデータ・自社単価・施主情報は公開しない。実案件との照合は手元で行い、数値だけ見せる
- 動画は公開される。権利のはっきりしない素材は使わない

## 10. 動画の構想（3 分）

トーン：Claude の広告「Keep thinking」の手法だけを借りる（映像・曲・タグラインは使わない）。
説明より映像と短い一文。「手」を主語にした同じ型の一文を場面ごとに繰り返す。前半は速いモンタージュ、作品の場面は長回し。
主役は人の手。AI は手の代わりではなく、手で考えることを広げるもの。

| 時間 | 時代 | 一言（画面の文字） | 映像のメモ |
|---|---|---|---|
| 0:00–0:20 | 手書き | 設計は、手から始まった。／Design began with the hand. | ドラフター、青焼き、手描きの実測図、三角スケール。鉛筆の音から入る |
| 0:20–0:35 | デジタイザ | 手の動きが、はじめて数値になった。／DWG = Drawing | デジタイザの写真に寄る。なぞると座標の数字が出る線画アニメ（自作） |
| 0:35–0:45 | マウス | 正確になった。手は、遠くなった。 | マウスの手元と細かいメニュー画面（自作の再現、他社ソフトは映さない） |
| 0:45–0:55 | タブレット | 手は戻った。でも、数値にはならなかった。 | iPad に描いた線を拡大すると、ただの点の集まり。無音 0.5 秒 |
| 0:55–2:30 | この作品 | 手書きのまま、モデルまで。 | 手元と画面の二画面、長回し。通り芯 → 図面と 3D → 構造 → AI 審査官の指摘 → 手で直す → 申請図書 |
| 2:30–3:00 | 限界と要望 | ここから先は、判断の速さが要る。／描く。数値にする。審査する。直す。 | 待ち時間の実測値、改善しうる領域。最後は無音 |

素材の方針：自社の古い青焼き・手書き図面と現場（施主名・所在地はぼかす）を主役に。
公的アーカイブ（国立国会図書館、ColBase、東京都立図書館、メトロポリタン美術館・クリーブランド美術館の CC0、
Wikimedia Commons、ジャパンサーチ経由の自治体アーカイブ）から権利の確かなものを補う。
東京タワーの設計図・建設当時の写真・外観は、早稲田大学歴史館・内藤多仲記念館・株式会社 TOKYO TOWER の許諾が出るまで使わない。

### 動画の方向（大会前に決めたこと・考えたこと）

- **メインのモチーフは墨壺、全体はモノクロ**。墨壺は手で「まっすぐな 1 本の線」を打つ道具で、作品の Apple Pencil も手の線を直線に整える。
  墨出しは今も現場の仕事。色を残すのは 1 色だけ（作品の線の色か、青焼きの青）。墨打ちの「パチン」を合図の音に
- **「Drawing」の二つの意味**：DWG は「図面」の意味で名付けられたが、この作品は「描くこと」を取り戻す話。
  冒頭はタイプライターで「.dwg」を打つ → 消す → 「Drawing」。最後は「Drawing, again.」で対にする。
  途中で DWG の中身（先頭の版の記号、例：AC1032）を数字の壁として見せる（AutoCAD の画面・ロゴは映さない。サンプルは自作）
- **参考の役割分担**：構成は Sony「Limitless」（原点の高速フラッシュ → 日常の集積 → 裏側の技術 → 種明かし → 円環）、
  デザインは OpenAI「Refreshed.」（白地に黒、主役は 1 つの黒い点、細い補助線、余白。ロゴ・書体・配色そのものは借りない）、
  イメージ想起は Claude「Keep thinking」。アプリ解説の見せ方は Anthropic「Let Claude handle work in your browser」
- **撮り方**：Post-it「Great Ideas」に倣い、代表が撮る素材はすべて真上からの俯瞰で統一。同じ机で、時代ごとに道具だけ替える
  （製図板と鉛筆 → デジタイザ風 → キーボードとマウス → iPad と Apple Pencil）。画面中央に常にペン先か 1 枚の図面を置くマッチカット
- **音**：タイプライター、鉛筆で線を引く音・字を書く音、紙をめくる音を、写真の切り替えに合わせて速めたり重ねたりする。
  最高潮で音楽を止め、Apple Pencil が画面を叩く「コツ」だけで作品名へ。本番は実際の音（代表が録る、または使用料なしの音源）
- 参考動画の共通項（代表の分析）：冒頭の「静」と短い掴み／細部と全体の行き来／過去から未来へ（モノクロから色と光へ）／
  人の表情と身体／音に合わせたカット割り／余白のある少ない文字
- 大会前に冒頭の試作を v1〜v5 まで作った（素材の並べ方と音の当て方の検討用。大会の提出物には使わず、期間中に作り直す）
- 動画の制作には、編集ページ（タイムラインに映像・文字・ナレーション・BGM・効果音を重ねる、カメラワークを名前で選ぶ）を使う構想
